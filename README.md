# travel-agent

从网页提问和生成行程的工作台已可本机运行。启动与试用见 [网页工作台](docs/WEB.md)。

面向国内旅行的多 Agent 规划助手。目标是把分散的攻略、地点、路线和费用信息整理成有依据、可修改的行程，并在购买等操作前由人审批。

## 当前状态

2026-11-09：完成 M1 需求解析和费用核算；M2 已有 DeepSeek 工具调用、搜索、高德地图、单 Agent 草案与首版预约主张分层检查。尚未完成独立事实认证、多 Agent、完整旅行覆盖或交易，尚不可正式上线。

本次新增受控单 Agent 基线：模型选择只读工具，服务端查证地点引用、摘要片段、时间和步行衔接，输出带缺口的草案。服务调用每次最高 2 元，高德免费配额耗尽后停止。它仍不是完整事实核验或已上线产品。

远程仓库：[s1ty0/travel-agent](https://github.com/s1ty0/travel-agent)。

## 核心需求

- 目的地支持“南京”“上海”等具体地点，也支持“南京附近”“上海周边”等范围。
- 预算支持“5000以内”“2000元”“2000～3000”，同时明确总额/每人/每天和费用包含项。
- 国内模型和来源优先，逐步融合攻略、地图、餐饮、交通住宿及后续供给。
- 多 Agent 按任务专精和并行；预算、时间、证据及权限由程序校验。
- 推荐附来源与获取时间，区分事实、估算和待核实项目。
- MVP 只读规划、修改、导出和平台跳转；后续交易实行具体动作审批。

## 如何继续开发

本轮已补资料导入、引文定位和授权快照重放。`POST /v1/references/inspect` 为本地离线检查；只有明确允许的资料进入模型，不自动抓取链接、不把匹配当作事实真实。

当前继续补 M2 的网页正文/身份、事实语义核验、真实接口重放与独立保留评测，再比较多 Agent。

已增加独立 `travel-agent-page --live` CLI，经两个精确公开网址真实验证。规划内可通过 `page_urls` 显式开放同一读取器，共享整次 2 元账本和来源次数；真实正文到草案引文定位已跑通。默认不保存完整正文，来源身份、语义和日期仍待核实；使用边界见 [正文读取说明](docs/PAGES.md)。下一步补来源身份与语义核查和独立评测。

预约要求可在活动 `claims` 中提交，由程序分别查身份、完整段落的有限文字支持和明确日期范围。另有本地离线 `POST /v1/claims/inspect`。当前规则很窄，结果始终保留事实未认证；复杂语义、独立身份、最新适用性和保留评测仍未完成。

现会比较本次全部已授权可用资料，提示重复关联、文字冲突与日期不足；不只看模型选中的引用，也不按多数票确认事实。比较不新增供应商调用，独立来源证明仍未建立。

新增结构化景点总数上限和 `--max-replans 1` 一次修正模式；默认仍是零修正基线，最多 4 次模型/5 次来源和每次 2 元上限不增加。10 条冻结合成契约通过；不是独立真实旅行评测，实际生成和事实核验仍有待验收项。

修正由程序限制范围，纯时间冲突不能删活动、缩短停留或改依据。v2 混合实验生成修正为 2/3；改用版本绑定的 [局部时间补丁](docs/TIME_PATCH.md) 后，v3 一次真实候选批次数量/交通/重叠 3/3，预算项请求前停止。初始冲突和来源仍为模拟，一次批次不能当完整真实旅行或稳定性验收，旧失败保留。详见 [实验说明](docs/REPAIR_EXPERIMENT.md)。

产品先做电脑/手机均可访问的响应式网站，包含需求、候选、规划工作台、版本和旅行详情。M4 主栈规划为 Next.js/React/TypeScript + Python/FastAPI；后续根据行中使用需求评估 PWA、小程序或 App。完整取舍、页面与部署/测试栈见 [PLAN 第 2.4～2.6 节](PLAN.md#24-产品形态网站先行多端按需求扩展)。这些前端能力目前是规划，不是已实现页面。

需要 Python 3.11 或以上，以及 uv。本次本地验证使用 Python 3.13.14、uv 0.12.5；应用和测试依赖已锁定于 `uv.lock`。

```powershell
uv sync --locked
uv run --no-sync travel-agent --destination "南京附近" --budget "2000~3000"
uv run --no-sync uvicorn travel_agent.api:app --host 127.0.0.1 --port 8000
```

本地 API 文档位于 `http://127.0.0.1:8000/docs`。`GET /health` 显示阶段；`POST /v1/intake` 解析专用目的地和预算字段；`POST /v1/budget/check` 核算声明范围内的费用。当前不从整段聊天自动抽取全部日期/人数，也不核实地图实体。

预算口径支持总额、每人、每天及每人每天。单值先作为目标；“以内”作为上限；区间下限默认是偏好。房晚、人数、税费与预备金分别核算；未知成本或未确认口径不显示为通过。API 返回金额单位为分。

```powershell
uv run --no-sync python scripts/check.py
uv build --out-dir artifacts/dist
```

测试报告保存在被忽略的 `artifacts/qa/`。当前全量指全部已实现的离线功能；真实集成、端到端、安全、性能与预发布测试仍是正式上线前的必需门禁。
