# 冻结合成规划验收 v1

先冻结 10 条验收契约及预期，再实现活动数量约束和有限重规划。样例位于 `tests/fixtures/planning_acceptance_v1.json`，文件 SHA-256 在相邻清单中；修改用例内容需新版本，不能为了绿色结果重写旧预期。

这是同一开发过程中编写的合成契约验收，不是第三方人工盲测，也不是未见真实旅行样例。脚本供应商返回固定资料和模型动作，能检查控制流程与已知约束，不能衡量真实模型稳定性、真实事实正确率或实际省时。原计划的独立人工/真实保留评测仍需另做。

## 十项契约

1. 明确只去一处景点：首次过多，允许一次修正后只保留一处。
2. 独立偏好“只去一处景点”：超出时不可放行为草案。
3. 交通衔接不足：在同一运行内修正间隔，计入原总预算与调用次数。
4. 时间重叠且修正仍错：达到一次修正上限后停止，不能反复尝试。
5. 旅行费用未知：保留 uncertain，不凑成零或宣称预算满足。
6. 预约依据不覆盖出行日：拒绝该份依据，不靠改写或删除事实核验来放行。
7. 同名不同实体且无路线数据：保留交通未知，不用名称猜成同一地点。
8. 多份资料文字冲突：保留冲突和事实未认证，不多数票决定。
9. 交易提示注入：权限错误即停，不借重规划扩大工具权限。
10. 修正前预算预留不足：停止并保留失败方案，不能新建账本或调用供应商后才检查。

## 使用与解释

`uv run --no-sync python scripts/evaluate_planning.py` 使用模拟传输，不读取环境密钥、不联网。报告保存在忽略目录 `artifacts/qa/planning-acceptance.json`。每条预期检查状态、调用次数、修正次数、初次/最终失败或未知状态；固定预期由显式输入和确定性约束给出，不用生成模型自评。

基线兼容读取旧结果：旧接口没有新字段时按一次最终提交计算验收观察次数，不存在修正能力就按 0 次；未知约束字段仍算契约未支持，不从输入删除后冒充已经实现。冻结前实现的首次完整基线为 5/10，其中一项为新字段未支持，不能把此数字当作真实旅行成功率。

验收通过只表示这 10 条模拟契约满足。不得用它替代来源身份、复杂语义、近似转载、多 Agent 对照、真实用户任务、安全、性能和预发布门禁。

## 本轮结果与保留记录

冻结用例提交为 `8a76828`，SHA-256 为 `95b753a363e3fc4e72974df671e03e25ff6de8d809a533bfd358e3e53e3437e4`。实施前基线 5/10；增加确定性景点上限与一次修正后为 10/10，原用例字节及预期未改。

评测驱动中的“修正仍重叠”场景最初误把第二次脚本提交改成正常间隔，与冻结场景意图相反；已修正驱动让其保持重叠，没有修改预期。零修正模式保留原最终路线复查，开启修正且景点过多时先返回数量反馈，避免为将被删去的活动查询路线。来源调用次数因模式不同而分别留痕。
