# 受控真实模型修正实验

本实验测量 DeepSeek 能否根据程序反馈修正已知冲突。初始模型动作、资料和地图全部由脚本供应，只有最后一个修正回合可显式联网。它不是完整真实旅行任务，也不是独立保留评测。

## 运行方式

默认离线，不读取密钥、不创建网络传输：

```powershell
uv run --no-sync python scripts/experiment_repair.py
```

显式开启真实修正模型：

```powershell
uv run --no-sync --env-file .env python scripts/experiment_repair.py --live
```

可用 `--scenario count|transfer|overlap|budget_guard` 单独选场景。默认执行全部四项；其中三项最多各一次真实模型调用，预算不足项应在请求前停止。`--output` 指定新报告路径，路径已存在时直接拒绝，默认路径带随机 ID，不覆盖旧失败。

真实请求仅到固定 DeepSeek 模型端点；数量候选只可调用 `submit_plan`，纯时间候选只可调用 `patch_plan_times`。本实验没有真实搜索、地图或页面请求，不需要高德 Key。默认各场景保持 2 元总上限；预算停止项使用更低的 0.26 元上限，验证原账本无法容纳下一次保守预留时，在调用前停止。没有购买、充值、升级或自动重试。

## 程序约束与评分

- 纯时间冲突只允许移动时间段。活动、日期、地点、类型、时长、引用和主张保持不变。
- 从 v3 起，纯时间候选只给 [局部补丁](TIME_PATCH.md)，绑定原版本和活动索引，程序派生结束时间；格式、错版本/索引或跨日错误整份停止，保留原失败。应用后仍冲突按生成失败计，不追加尝试。
- 数量冲突允许删除原活动或移动时间段；剩余活动的其他字段与时长不变。不能改成餐饮来逃过景点计数，也不能重复或新增活动。
- 逐日覆盖冲突允许重建活动，仍须通过所有既有校验。这是明确例外，不宣称此模式也冻结活动。
- 重叠反馈包含已知路线所需间隔，含原有 10 分钟缓冲。未知路线仍未知。
- 范围违规返回 `repair_scope_violation`，不再修正，也不为违规候选追加路线查询。

生成成功必须同时满足：最终草案无确定失败、保留初始失败及第二次校验、只请求一次候选、来源调用数不增加、原账本上限不变、未知事实/旅行费用保留，以及与实际初始活动组合核对通过。安全拒绝是边界工作正常，不能算生成成功。

## 计费与留存

规划账本包含脚本初始模型与搜索的模拟费用，不能当成真实账号账单。报告分别记录模拟初始费用和真实候选按当前价格卡高价估算的微元数；1 元 = 1000000 微元。真实用量不明时该项为 null，不按零处理；供应商实际账单始终另列，未对账时为 null。

报告只保存版本、运行 ID、哈希、规则、次数、耗时、费用和状态，不保存完整提示、旧/新完整方案或供应商原文。报告保存在忽略目录，公开开发日志记录脱敏摘要。默认离线测试验证无网络、无密钥读取、预算先阻断、无自动重试、不覆盖报告和错误脱敏。

## 历史与当前结果

`hybrid-repair-v2` 的一次真实批次：数量与交通修正通过，重叠修正违反原活动范围被拒绝，预算项调用前停止。生成修正为 **2/3**；预算停止为 **1/1**。总体报告仍失败，不算 3/4 的旅行成功率。共 3 次真实模型、0 次真实来源，费用上界估算合计 0.019652 元，实际账单未对账。

早期 v1 的实验评分错误及真实失败记录均保留。没有反复付费重跑至全绿。详细过程见 [开发日志](devlogs/2026-11-09-live-repair-experiment.md)。真实冲突修正稳定性仍未验收，默认零修正不变，未部署。

`hybrid-repair-v3-time-patch` 改用局部时间协议后，2026-11-10 的一次新批次生成修正 **3/3**，预算停止 **1/1**，总体通过。数量项仍为完整提交；仅交通/重叠项使用时间补丁。共 3 次真实模型、0 次真实来源，候选费用上界估算合计 0.018554 元，实际账单 null。没有追加同版本付费尝试。

这三个已知上下文的单次结果不证明统计稳定性、跨协议显著提升或完整真实旅行质量。原 v1/v2 报告不覆盖，默认零修正及上线阻塞不变。详见 [补丁联调日志](devlogs/2026-11-10-time-patch.md)。
