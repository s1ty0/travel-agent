# 多份预约资料的一致性检查

本模块检查本次已取得、已获准共享的资料是否说法相反，以及重复或可能共源的引用。不判断多数票，不证明来源独立，也不自动认证现实规则。

## 输入与权限

规划活动出现预约 `claims` 时，程序检查该主题对应的全部可用资料，不只看模型选中的来源。未获准共享的资料不进入规划比较，未读取的网页不能凭 URL 补正文。只沿用 `reservation-rule-v1.1` 的完整段落有限句式；摘要、链接和复杂条件不算完整预约规则。

单条引用核查与资料比较分开。其他正文支持主张，也不能替模型修复编造、未读取或错误的引用。

## 重复与可能共源

同一输入版本重复出现只计算一次。不同版本按以下线索形成候选关联组，但全部版本继续参与比较，不用一份代表覆盖其他版本。

| 线索 | 处理 | 不能推出 |
| --- | --- | --- |
| 规范空白后正文相同 | 标记相同规范文本，保留原始哈希。 | 不证明实际抄袭或共同作者。 |
| 声明网址相同 | 标记同一声明定位，保留不同正文版本。 | 不默认最后取得的版本更真实。 |
| 声明主机相同 | 标记可能共源，允许传递关联。 | 同站未必同作者，异站也未必独立。 |

只解析声明网址，不解析 DNS、不请求网页、不认证发布者。近似改写、转载链、作者身份和注册域归并尚未完成。候选组数不是独立来源数。

当前 `independence_status=not_established`、`independent_confirmations=0`、`facts_verified=false` 始终保留。更多 Agent 或五份重复说法都不能抵消另一份相反规则。

## 日期与冲突

活动日期作为出行日；适用范围只认同一完整规则段落中明确的双边年份日期。采集时间、发布日期或 URL 日期不作为生效范围。

| 状态 | 含义 |
| --- | --- |
| `conflict` | 相反的明确文字规则，双方声明范围均覆盖出行日；不判断哪条现实规则正确。 |
| `potential_conflict` | 说法相反，但出行日或适用范围不足，不能断言同日冲突。 |
| `different_textual_periods` | 出行日未定，相反说法的明确文字范围互不重叠；不自动宣布替代关系。 |
| `no_detected_conflict` | 有可查规则，在有限句式和本次范围内未检测到冲突，不是规则已确认。 |
| `insufficient` | 缺少足以比较本次要求的正文规则。 |
| `incomplete` | 来源/规则截限或同 ID 多版本，不能声称比较完整。 |

有出行日时，明确范围不覆盖该日的规则保留并计数，但不作当日冲突的证据。非法范围也不参与有效比较。没有结束日期时不擅自补成永久有效。

## 上限与版本

比较版本为 `reservation-comparison-v1`：最多 32 个来源版本，每源最多 20 条不同值/日期组合。同一组合反复出现只增加出现次数，不成为新规则或新证明。

截限设置 `limit_reached=true`。已发现的冲突仍保留，但 `complete_within_bounds=false`；尚未发现冲突则报告未完整完成。同 ID 不同内容/类型/网址版本标为 `source_id_collision`，不覆盖其中任何一份。

`complete_within_bounds` 只说明没有遇到这些数量/标识边界，不表示完成全文语义、官方身份或独立来源验证。`full_semantic_verification=false` 始终保留。

## 输出与留痕

离线 `POST /v1/claims/inspect` 增加 `comparisons` 和 `cross_source_summary`，不联网、不保存正文。获准保存的合成快照可重放同一比较结果。

规划活动的 `evidence_comparisons` 展示已识别规则、文字日期、上下文位置/指纹和候选关联。Markdown 提示冲突或不足，不展示多数票结论。跨资料冲突记为 `cross_source_consistency=unknown`，不将不明真假的说法当现实硬约束；原有无效引用仍可单独使方案失败。

比较不增加模型、搜索、地图或 Fetch 请求，不改变每次 2 元上限。审计只存比较版本、指纹和状态计数，不存主题、规则原句、完整正文、网址或主机。指纹绑定主题、日期、输入版本、上限和算法，且不受来源顺序影响；哈希不是匿名化或防篡改签名。

过程见 [本轮日志](devlogs/2026-11-09-m2-evidence-comparison.md)。合成回归已用于开发，不是独立保留评测或真实跨来源事实质量验收。
