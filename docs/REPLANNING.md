# 景点数量约束与有限重规划

本模块处理已知时间或数量冲突，不认证营业、价格或票务事实。修正始终属于同一次运行，复用预算、来源、路线、缓存与截止时间。

## 明确景点上限

规划输入增加 `constraints.max_sightseeing_places`，严格整数 1～9，表示整个行程中声明为 sightseeing 的不同地点来源 ID 数量上限，不是每天活动数或至少要去的数量。

```json
{"constraints":{"max_sightseeing_places":1}}
```

这是加入完整 `city/trip` 输入的字段片段。相同来源 ID 重复参观只算一处；同名但不同 ID 不静默合并。声明为餐饮和休息的活动不计入景点数，每天最多 3 项活动的原规则仍生效。活动类型来自结构化模型提交，本轮没有独立核实地点实际用途；误分类和别名实体仍需后续检查。

偏好仅支持完整独立短句的窄解析，例如“只去一处景点”“只安排1个景点。”“最多一处景区”。带条件、否定、引用、多个要求或不匹配句式不自动提取。`raw_text` 不做通用数量抽取；正式硬上限优先使用显式字段。

显式上限与可识别的独立短句同时存在时取二者交集，不能放松更严格的要求。结果 `plan.constraints` 和模型上下文里的 `effective_constraints` 展示生效上限、显式值和短句识别标记，其他偏好保持 `not_fully_validated`。

## 开启一次修正

默认 `PlannerLimits.max_replans=0`，保留零修正单 Agent 基线。CLI 显式加 `--max-replans 1` 开启最多一次：

```powershell
uv run --no-sync --env-file .env travel-agent-plan --live --max-replans 1
```

仍从 UTF-8 stdin 读取完整规划 JSON。只允许 0 或 1，不增加默认最多 4 个模型回合、5 次来源调用、90 秒及 2 元服务上限。若首次提交已经耗尽模型回合，则不能再修正；开启不保证一定修正。

仅对时间重叠、已知交通间隔不足、每天活动数、景点上限和逐日覆盖的失败进行一次反馈。所有失败必须属于该白名单；引用、事实依据、格式、权限或供应商错误不靠重规划绕过。只有未知条件而无确定失败时也不触发。

程序返回 `revision_requested` 与具体失败数值给原 `submit_plan` 调用 ID，保留模型自己的工具历史；不是伪造模型调用。仅纯时间失败时，下一回合只提供并接受 `patch_plan_times`，数量/覆盖模式仍只接受 `submit_plan`；不允许模型借修正请求新的搜索、地图或网页工具。

反馈的 `repair_scope` 指定程序强制执行的修正范围。仅时间失败时，只能移动起止时间，活动、日期、地点、类型、停留时长、引用与主张保持不变。数量失败可额外删除原活动，不能新增、复制或改类型。逐日覆盖失败允许重建活动，仍执行完整校验。前两种模式以活动签名多重集合比较，不仅比较地点 ID。

纯时间模式使用 [time-patch-v1](TIME_PATCH.md)，只给原提交版本指纹、原数组活动索引和新开始分钟。结束时间由程序按原时长派生，未列活动不变；错版本、索引、跨日和格式错误整份拒绝，停止并保留旧失败，不提交半份补丁。

违反范围返回 `repair_scope_violation`，方案为 invalid_plan，不再修正，也不为该份候选追加路线查询。重叠反馈包括已知路线所需分钟数和原 10 分钟缓冲，缺失路线时不伪造数值。

最终方案若改变路线端点，程序仍可在同一来源上限和免费模式内复查准确路线；这不是模型额外查源权限。已有路线直接复用。缺少路线或余量保持未知，不借时间改写伪造交通事实。

零修正基线保留最终路线复查。开启且仍可修正时，数量过多先返回数量冲突，暂不查这份可能删减的路线；修正提交再按实际端点检查。

## 何时停止

- 修正后仍有确定失败：返回 `invalid_plan`，不再请求第二次修正。
- 预留费用不足、价格/用量不明、超时、格式/权限错误：立即 `stopped`，不会新建账本或重启运行。
- 需要修正但模型回合已用尽：保留未通过方案，不增加回合。
- 原有缺失价格、未认证身份、来源冲突或未知营业继续保留，不能为绿色状态改写成通过。

`replans` 记录已请求的修正次数，不是成功次数。修正请求后可能在模型请求前就因预算停止；此时 model_calls 不增加，不能把请求计数当成已付费调用。

## 输出与留痕

`validation_attempts` 保留每次完成校验的方案哈希、状态、失败规则、修正模式、可选补丁指纹 `time_patch_sha256` 和当时累计模型/来源次数；不默认保存原始补丁时间、旧完整方案、主张原句、地点名或提示。修正完成的新方案替换终端最终展示，历史失败元数据不删除。

修正失败停止时，顶层 `status=stopped`，`plan` 可保留最近的 `invalid_plan`。Markdown 明确提示停止及原因，不能将保留的方案当新成功草案。SQLite 保留相同的最小校验轨迹与计数，费用只看同一顶层总账本。

冻结验收、基线比较与边界见 [EVALUATION.md](EVALUATION.md)。一次真实规划满足景点上限不代表已经触发或验证真实模型的冲突修正；模拟结果和真实结果分开报告。

已有显式真实候选模型的 [受控混合实验](REPAIR_EXPERIMENT.md)，初始冲突和来源仍模拟。v2 批次生成修正 2/3，改局部时间补丁后的 v3 一次批次 3/3；真实稳定性和完整旅行仍未验收，安全拒绝不当作生成通过。
