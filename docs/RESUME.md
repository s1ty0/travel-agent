# 简历项目与面试说明

项目名称：**行迹：带来源与约束校验的多Agent旅游规划工作台**。

技术栈：Next.js / React / TypeScript、FastAPI / Pydantic、DeepSeek、HTTPX、SQLite WAL、pytest、Vitest、Playwright、GitHub Actions。多Agent为自建固定分支汇合，不写LangGraph、RAG向量库或未实现的商业接口。

## 可直接改写到简历

- 开发响应式AI旅游规划工作台，支持自然语言首稿、1～3天行程、真实地点及附近餐饮候选、版本对比、局部修改和Markdown导出，打通Next.js、FastAPI与独立任务worker。
- 设计联合研究、并行工具、体验/餐饮双Agent三种策略，统一来源ID与确定性时间/交通/逐日约束；用共享微元账本原子预留每次5元服务预算，费用未知或免费地图配额故障时停止后续调用。
- 基于SQLite事务实现任务幂等、独占认领、租约心跳、取消、中断不自动重放、私有会话逐资源授权和7天版本保留；明确局部修改复用证据并冻结其他日期，降低不必要的模型重生成。
- 建立30个冻结合成工程场景的三策略回归和桌面/手机端到端测试；一次10例真实模型/固定来源验收符合预期（6草案、4拒绝），另一次全真实来源双Agent冒烟观察到1076毫秒请求重叠。保留失败、费用及未知事实，提供一键无密钥演示和可复现报告。

## 面试如何讲

**为什么多个Agent？** 体验与餐饮可以并行，输出通过ID合并，权限和预算由同一个程序控制。三例对照显示专精成本更高，尚不足以改成默认；因此保留联合默认和可切换实验，不以Agent数量作为成果。

**为什么不用模型直接排完？** 名称、精确时间和价格容易失真。模型负责候选取舍；地点只从实际来源解析，交通用精确端点，时间/数量/禁去/逐日由程序检查。未知路线不能自动判通过，仍可交付有缺口的草案。

**如何避免重复收费？** 请求与任务创建、worker认领分别事务化；同ID不同内容拒绝，删除后保留墓碑；失联任务不自动重放。供应商调用本身不具备统一幂等保证，因此不能宣称“所有外部调用恰好一次”。

**5元是否绝对账单封顶？** 不是。程序按已知价格高价估算并原子预留，未知用量停止且保留未结算金额；供应商实际账单仍需对账。高德依赖账号免费且没有付费回退，不由程序代改套餐。

**修改为什么可控？** 识别明确日期、结束时间、步行上限、排除来源ID及预算；只重排涉及日期。证据复用不代表新路线已知，删点后新相邻端点需要补查。当前“换掉”仅移除并要求另选，不能夸成任意智能替换。

**失败学到了什么？** 初期5次来源额度不足以同时查多天地点、餐厅和路线，且模型交替查询可能耗尽最终提交机会。后续改为来源先行、有限研究和程序排程；修复高德限速竞争、Windows孙进程泄漏、未知路线当零步行、长HTTP缺进度误触租约、重研究带回禁去地点等问题。具体失败可查开发日志。

**下一步是什么？** 扩大带人工核查的真实旅行评测；补周边城市候选、交通酒店授权、正式身份和运维。购买审批目前是边界设计，没有真实交易工具；不能展示为已实现的自动购票闭环。

## 诚实口径

当前为本机可演示MVP，未公网部署；演示地点与路线为合成，真实模式单独显式开启。没有确认小红书/美团全量搜索授权，没有实时票务酒店库存，没有注册账户或跨设备恢复，没有用户省时数据。AI辅助开发应按面试要求说明，展示自己能解释、复现和修改代码的证据。
