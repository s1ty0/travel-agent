# ADR-0020 专精研究与三策略对照

日期2026-11-11。状态采用。网页保留标准研究默认，可切换并行查询、专精并行；不因为引入多个Agent就宣布更好。

`source-first-v1.1`先收集相同城市的搜索、兴趣地点及餐饮候选。体验研究输出景点ID/天数/停留时长，餐饮研究输出查询词与真实候选餐厅ID；协调程序仅从实际附近结果选择餐厅，严格剔除不存在的候选ID并记录计数。来源文本不能修改权限、预算或触发交易。

三种策略共用来源适配、编排、约束与每次5元账本：标准模式顺序查询并一次联合研究；并行工具模式并行查询后联合研究；专精模式在查询后并行运行两个独立DeepSeek请求。联合输出最多2048 token，专精1536+512，输出总上限相同；专精输入上下文重复，输入用量和调用数并不相同，报告必须披露。费用预留在同一账本原子执行，分支错误不解除原费用/时间/次数限制。

冻结20条开发及10条发布验收样例，文件SHA-256随仓库保存，不能改预期以获得绿色。都是本项目编写的合成工程场景，不是第三方盲测或独立真实旅行质量集。预期无解/拒绝单独计数，不合并为生成成功。

同源对照使用固定合成来源及真实模型，每个案例/模式一次，来源模拟延迟20毫秒，不能把其耗时叫真实端到端网络耗时。另执行一个全部真实来源的多Agent冒烟，记录两角色请求区间重叠。小样本结果只用于本次取舍，不声称稳定提升比例或用户省时效果。

本次三例对照均生成无已知硬约束错误的草案，专精中位1518毫秒、标准1704毫秒，但专精模型估算合计更高。保留标准默认，专精可选；后续扩大真实、人工核查的评测后再决定默认策略。
