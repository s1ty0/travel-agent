# ADR-0007：受控供应商正文读取与核验分层

日期：2026-11-08。状态：采用于 M2 的独立读取适配器。承接 ADR-0006 的正文获取待办，不改变用户资料独立授权规则。

## 问题

已实现的正文导入只能证明用户提供文本里的引用存在，搜索摘要也不能替代网页正文。需要真实读取接口，但不能把供应商转换文本、请求网址和官方事实混为一谈。

## 决定

1. 使用已有 DeepSeek 账号的 Fetch 接口，首轮只允许两个本轮开发中检查过的精确公开网址；不做任意网址抓取，不传目标网站 Cookie，也不从页面内继续请求。
2. 供应商只保证其响应契约，当前没有最终网址、跳转链、签名或抓取时间证明。保留 `provider_markdown`、请求地址审查范围、来源未认证、日期未知、语义未评估及事实未核实等独立状态。
3. 正文只在运行内使用。默认终端输出与 SQLite 审计均只含最小元数据；显式终端展示正文不等于取得复制许可，真实 API 全文快照继续待核实。
4. Fetch 与搜索同为每次成功请求 0.005 元，复用可传入的同一费用账本。未知计费保留预留并停止；策略和价格过期均阻止调用，不重试、升级或充值。
5. 本轮先交付独立 CLI，验证真实接口、状态和预算。单 Agent 自动读取需后续共享总账本、工具上限、来源策略和证据类型后接入，不能提前标成已完成。
6. 精确引文匹配沿用同一纯函数，避免用户正文和供应商正文采用不同位置规则；位置对应收到的 Markdown，不对应网页 HTML。

## 取舍与后续

精确网址白名单覆盖很窄，但能把第一轮真实读取的边界做实。新增来源要记录访问范围、身份线索、有效期、留存许可及失败处理；仅添加域名后缀不能完成官方身份认证。

仍需独立来源身份与语义核查、最新规则适用性、独立保留评测、真实响应重放许可及规划集成。本决定不将 M2 或产品上线标为通过。
