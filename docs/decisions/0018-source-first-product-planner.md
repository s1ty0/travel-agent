# ADR-0018 来源先行与确定性日程编排

日期2026-11-11。状态采用。简历MVP的网页默认使用`source-first-v1`，旧工具调用基线保留供CLI、冻结回归与对照，不覆盖历史实验。

旧引擎由模型同时选择地点、调用查询、安排时刻并修正冲突，有限回合内多日和交通稳定性不足。新引擎先取得搜索与固定城市的地图候选，研究输出只允许选择地点ID、天数与建议停留时长，餐饮输出限于查询词；餐厅由地图周边查询提供。地点名、地址和路线仅由实际返回记录补齐。无效或重复ID剔除，缺失天数可据剩余真实地点提供明确标记的保守初稿，不能伪装偏好已满足。

`constraint-scheduler-v1`按每日范围、停留时长、真实步行估算与10分钟缓冲派生时刻，不缩短必去活动凑时间。为遵守明确步行上限可减少较远的可选景点并说明；必去/排除冲突、时间不足仍失败。删减后重新核对相邻地点自己的路线，不能借用旧边。午晚餐给出地图餐厅候选，营业、预约、价格、口味适配和完整费用仍未知。

新引擎每次最多8次模型、20次来源、180秒，含想法解析共用5元原子账本；旧基线仍4次模型、5次来源。不是增加到5元就花满或无限重试。并行上下文保留角色起止时间和调用用量；一条分支失败可保留其他已知结果，未知用量与来源故障停止继续消耗。接口失败后保留已取得的部分方案和缺口，整体状态仍为停止。

真实高德调用在进程内保守间隔1.05秒，不重试被拒请求。仅保留五位数字供应商错误码；限流/额度耗尽/权限错误按官方分类，不回显供应商info或密钥。首次未分类拒绝没有足够证据追溯为某种具体配额错误。依据：[高德错误码](https://lbs.amap.com/api/webservice/guide/tools/info)。

单Agent、并行来源工具和并行专精Agent使用相同来源与程序编排。单Agent一次联合研究、专精模式两次独立研究，调用次数差异必须在报告中披露。S1已实现模式和离线并发验证；真实公平对照及效果报告属于S3，不能提前宣称性能提升。
