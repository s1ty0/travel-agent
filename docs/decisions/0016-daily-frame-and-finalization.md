# ADR-0016 每日时间框架与完整性提示

日期2026-11-11。状态采用。补充ADR-0015的收尾策略和ADR-0014的网页交互；CLI默认零修正保持不变。

用户反馈杭州草案只有09:00～11:30、13:00～15:00的两项游览。旧实现最多每天3项地点活动，没有每日范围，也没有展示用餐和晚间空白。最小审计只表明逐日覆盖失败，不能从旧记录精确还原请求天数或缺失的具体天数。

网页增加独立的每日时间范围，默认09:00～20:00并列为假设，可在更多条件中修改。没有要求用户必须玩到20点。单日/多日草案均按范围展示已取得地点活动及未落实时段；短句续写保留上一版范围。没有明确数量要求时不再隐含全程2处景点上限。

程序派生`day-frame-v1`，不移动、延长或新增原地点活动。60分钟午餐优先12:00、晚餐优先18:00，分别在11:30～14:00、17:30～20:00内寻找空档；已提交的用餐活动不重复填充。地点间空档整体显示为转场/用餐建议，已知步行时间向上取整加10分钟缓冲，剩余空档不足时报告缺餐。未知交通不能宣称用餐和转场均可完成。同一地点不伪造交通。其余留白显示休息、自由活动或晚间/返程待确认。

整天没有地点活动时只显示“这一天尚未安排”。用餐与留白不是已查询的餐厅或夜游项目，不增加价格、不确认营业，也不解除逐日覆盖、交通、费用和事实检查。范围外活动构成可修正时间错误。前端与Markdown均显示具体缺失天数和已有交通冲突，日程审计只保存规则版本与计数。

网页默认一次已知冲突修正，可关闭。搜索与地点就绪时最迟在倒数第二个模型回合进入提交，保留可能的修正余量；参数模式列出真实地点ID与请求天数，增加明确收尾指令。收尾阶段不执行新增查询，无效查询参数被丢弃，不阻断整理；有效缓存继续复用且不增加调用或费用。模型回合最多4次、来源5次、整次2元和高德免费额度边界保持不变。提交的参数和行程仍按原规则完整校验，模式枚举不是供应商必定遵守的保证。

模型格式错误只保留白名单字段名及错误代码，不存原始响应、被拒绝值或未知字段名。2026-11-11真实联调既保留格式停止，也保留两日覆盖但交通仍失败的结果。本决定改善完整性展示和收尾，不代表已完成用餐/夜游检索、多日优化或真实旅行质量验收。
