# ADR-0015 首稿优先与查询上限后的提交

日期 2026-11-10。状态采用。调整 ADR-0014 的先确认再生成交互，补充既有规划调用上限规则。

用户试用时，5 次来源已取得搜索和多个地点，第三模型回合再次请求查询，触发立即停止并返回空行程。原实现只在最后一个模型回合强制提交，来源次数比模型回合先用尽时缺少正常收尾。

新增查询在来源上限处记录为未执行，并向原工具 ID 返回具体反馈。后续模型回合只开放 submit_plan，已有缓存继续可用，整次原预算与调用限额继续执行。必要搜索/地点不足、模型仍不提交、费用/用量不明或供应商故障继续返回真实缺口，不能补造路线和事实。

网页发送想法直接创建首稿任务，字段提取算一次模型调用并进入同一费用账本、4 次模型上限及截止时间。提取值需出现在原文，天数缺失时以明确假设暂按1天，其余缺项保留未知。生成后可补结构化条件或短句，上一版条件必须由服务端按当前会话读取。前端更新时保留旧版结果，并提供上一版切换。

来源额度与服务费用额度是独立边界。修复空结果的手段是提前收尾与保留已有依据，而不是通过花满 2 元扩充调用。后续持久版本、任务恢复、全局配额及生产身份继续按 PLAN 推进。

追加实测发现，模型有时在强制提交回合仍继续请求工具。网页额外开启单日程序起草，只在模型回合用完且没有提交、已取得搜索与真实地点时触发。每天时段明确为建议，本版仅覆盖单日，保守选择一个非停车/入口/售票类地点，09:00 停留60分钟，再执行原校验。输出和审计标明程序起草及偏好/用途待核实。来源故障、未知费用和已经提交的无效方案不进入此路径。CLI 默认基线保持原模式。
