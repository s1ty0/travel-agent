# ADR-0011：冻结规划契约与有限修正

日期：2026-11-09。状态：在单 Agent 内采用，作为后续 M3 对照基础，不等于 M2 或多 Agent 整体验收完成。

1. 在实施前冻结 10 条合成验收契约并保存字节哈希，保留前后结果；同一开发过程编写的用例不能冒称第三方盲测或真实独立保留评测。
2. 景点数量使用明确结构化上限；独立短句只做窄解析，显示生效约束，不把全部自然语言偏好宣称为已验证。
3. 默认保留零修正串行基线，显式设置最多一次修正。修正共享整次运行的费用账本、来源上限、模型回合、时间和缓存，不另开 2 元额度。
4. 修正只接受已知时间/数量/逐日覆盖失败，返回程序定义的具体规则和数值。下一模型回合仅允许重新提交，不新增工具权限；程序对改变后的最终路线继续按准确端点核查。
5. 引用/证据/权限/供应商错误与未知条件不靠修正绕过。失败仍在、额度不够或回合耗尽时停止，不隐藏失败后重新启动。
6. 最小审计保存每次方案哈希和失败规则，不保存旧完整方案或原始提示。中止时顶层停止，最近失败方案可供诊断，展示时必须明确未通过。

先用冻结合成契约验证程序流程，再分别核对真实模型生成与真实冲突修正。不能用脚本提供的“改好方案”宣称真实模型已经更可靠。多 Agent、完整事实核验、独立真实评测和产品上线仍按各自门禁推进。

详情见 [修正说明](../REPLANNING.md) 和 [冻结验收](../EVALUATION.md)。
