# ADR-0008：规划内网页工具与共享预算

日期：2026-11-08。状态：采用于 M2。承接 ADR-0007，替代其中“Fetch 仅独立 CLI、尚未接入规划”的当前实现状态；保留独立 CLI 和全部来源核验边界。

## 问题

独立 Fetch 已能取得供应商正文，但不在规划工具回合中。简单再套一层调用会产生独立 2 元额度、超出来源次数、重复保存全文或将“网址已审查”错误当成事实认证。

## 决定

1. 规划输入新增 `page_urls`，默认空。用户明确列出某个已审查公开网址，才允许本次读取并送模型；这不是必须读取的指令。导入普通链接或模型自行发现链接不增加权限。
2. 只有列表非空才向模型开放 `read_page`，工具 schema 列出本次地址枚举，服务端仍独立验证精确网址及本次范围。没有网页工具时继续保留原基线。
3. 向现有读取适配器传入整次规划同一个费用账本、价格卡、日期、剩余超时和来源传输层。实际 Fetch 次数计入默认 5 次来源总额，与搜索、地图和最终路线复查共用，不再为网页建立新 2 元预算。
4. 同运行内相同读取复用结果；成功才缓存。网页失败或费用未知立即停止剩余工具及后续模型，不隐式重试、回退或续费。
5. 模型只收到供应商 Markdown 与未核实元数据。程序在实际取得的版本里检查引文，返回精确码点位置、指纹和证据类型；未读取、编造、歧义或偏移错误不能通过。搜索摘要也采用相同逐字定位规则，重复时需明确位置。
6. 不静默截断正文以塞入上下文。加入正文后若总请求超过 48000 UTF-8 字节，立即停止，避免继续查询其他来源或再调用模型。
7. 输出和审计只增加网页最小元数据及父子运行 ID；正文、供应商标题和完整对话不自动保存。最终规划账本是费用总计，子读取不重复列累计账本，避免相加造成双重计费展示。
8. 单独记录正文是否进入了模型请求尝试。`request_attempted` 只证明本地请求尝试带上正文，不能认证供应商实际读取、理解或内容真实性。

## 保留边界

读取地址审查、内容身份、语义支持、日期适用性和现实事实分别判断。当前后四者仍未知/未评估，行程仍是草案。没有新 HTTP 付费路由、购买、预约、支付或任意网页读取能力。

后续补来源身份独立证明、语义与时效核查、许可范围内真实重放、独立保留评测和规划质量，再按 M2/M3 验收推进。
