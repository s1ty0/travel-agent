# 恢复真实城市规划与10次试用

用户在公网试用时被两城区限制拒绝，明确指出助手偏离旅游规划产品设计，要求撤销限制、试用提高为10次，并要求以后产品变更先说明影响并确认。此前限制来自助手在 Vercel 环境强制启用 OSM 快照，非模型或高德不支持其他城市。已将规则写入长期记忆；本记录与 ADR-0023 替代此前受限首发方案。

实现移除 Vercel 强制 OSM 的逻辑，生产显式使用高德真实查询；前端不再收到两城白名单。保留真实故障与来源缺口，不回退合成地点。会话及同网络滚动24小时上限改为10，前端说明同步；全站累计10次由用户另行明确确认，既有次数不清零。

## 验证过程

- 新增南京、上海、成都的云端路径回归，确认 Vercel 环境使用高德适配器，未被旧快照城市表拦截。会话、换 Cookie、换网络和全站累计限额测试按10次边界验证。
- 本机冒烟13、固定回归65、原冻结验收10/10、全量675项通过，2个 PostgreSQL 集成单列；覆盖率93.16%。前端23项、格式、类型与生产构建通过。
- 候选南京实际生成南京博物院、寻魏·金陵十二菜、六朝博物馆、萱记深井烧鹅，2次真实模型、1次搜索、3条真实高德路线，无已知硬约束错误，服务上界估算0.015818元。验收脚本随后因供应商排序断言写反而失败；这是脚本问题，不重付费生成来筛选结果。费用为估算，实际账单未对账。
- 本机真实 Neon 复核中一个并发场景连接被服务端断开，另一个10次网络限额场景通过；记录为1失败1通过，不写成两个通过。最终提交另在 CI 的独立 PostgreSQL 17 验证。
- 本机浏览器回归初次复用了已存在的真实开发服务，离线保护断言在首稿提交前拒绝；已隔离本机环境文件和服务后重新执行。
- 上一资料提交的网页 CI 因 Ubuntu 软件源 DNS 解析失败，未进入浏览器测试。现使用运行器自带 Chrome，保留完整桌面/手机流程，不依赖重复安装系统字体包。依据：[GitHub运行器软件清单](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md)、[Playwright浏览器通道](https://playwright.dev/docs/browsers)。

## 发布结果
