4. 检查发现 CLI 只配置输出编码，未固定标准输入编码；已改为 UTF-8，增加强制非 UTF-8 平台默认编码的子进程回归。
5. 第二次使用直接 Python 调用和只输出结构元数据的诊断传输验证：HTTP 200、字段结构正确、实际模型 `deepseek-flash`，输入 202、输出 17 tokens。
6. 第三次在最终 CLI 上验证：成功提取周边目的地和预算上限，保持草案；实际模型 `deepseek-flash`，输入 202、输出 17 tokens。

本轮共尝试 3 次模型请求，每次最多输出 512 tokens；未自动重试。首次失败调用用量未知，不据此捏造总费用。没有调用搜索、地图、订单或支付。成功请求不代表整个旅游系统已经可用。
