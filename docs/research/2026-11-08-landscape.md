# 首轮调研：旅游助手、接口与可复用组件

调研日期：2026-11-08（Asia/Shanghai）

范围：中国境内旅行优先，国外能力作为后续参考。

方法：公开网页、平台官方文档、项目原仓库；不登录业务账号，不试购，不调用付费业务 API。

## 1. 先给结论

1. **产品方向已有验证，项目仍有可做的差异。** 飞猪、TripGenie、Mindtrip 已覆盖旅行规划的不同环节。我们的候选差异是跨来源证据、预算与路线校验、可修改版本及明确交易审批。这是产品假设，尚未证明优于现有产品。
2. **先复用工具和流程，谨慎移植整套 Demo。** LangGraph 的持久化/中断、高德的地理能力、国内搜索 API 都值得验证。旅行样例可学角色与接口结构，但不等于国内可用的完整产品。
3. **国内存在正式搜索入口。** DeepSeek 和 GLM 有结构化联网检索文档；知乎官网列出搜索、直答和 MCP；抖音有需申请权限的视频搜索。账号资格、覆盖、费用和效果仍需实测。
4. **小红书仍是首版的数据不确定项。** 找到了官方账号授权、小程序/分享能力和社区搜索 MCP；本轮未确认面向本项目开放的官方全站笔记搜索 API。不能据此断言“小红书没有任何官方搜索合作”。
5. **平台 AI 总结可以复用，但不能自动升级为事实。** 先辨认是否有底层引用；重要事实回查对应来源。没有来源就作为二手线索展示。
6. **首版无需依赖购买。** 先实现带证据的只读行程，真实库存、下单和付款按权限分阶段接入。

## 6. 通用组件的复用优先级

| 组件 | 适用部分 | 取舍与证据 |
| --- | --- | --- |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 编排、并行汇合、状态、人工中断。 | 首选验证。官方 [Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) 与 [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 支持暂停恢复和检查点；仓库 MIT。中断不是完整交易权限系统，恢复也可能重跑节点。 |
| [Google ADK](https://adk.dev/agents/workflow-agents/parallel-agents/) | 专项角色、工作流和并行执行。 | 备选。官方也提供 [多模型接入](https://adk.dev/agents/models/) 入口，不能说它只能使用 Gemini。与国内模型、恢复及审批的具体组合尚未测试。 |
| [OR-Tools](https://github.com/google/or-tools) | 路线和复杂约束求解。 | Apache-2.0。[时间窗路线示例](https://developers.google.com/optimization/routing/vrptw) 可学建模；不能自动提供真实地图、营业或票务数据。先做普通规则，复杂后再引入。 |
| [Langfuse](https://github.com/langfuse/langfuse) | 模型/工具追踪、成本和评测。 | 可选，先本地结构化事件；仓库说明 MIT，但 `ee` 目录例外，复用范围单独核实。任何云端遥测先脱敏并确认保存位置。 |

底层数据、模型供应商和编排框架分开。优先采用标准接口和小适配器，不为使用 MCP 或多 Agent 而额外引入不必要服务。

## 7. 小红书总结能否直接用，是否应该取 TOP50

本质：**总结适合压缩信息；底层证据负责支撑事实。采样数量由缺口和预算决定。**

| 拿到的结果 | 可以怎么用 | 进入正式行程前还需什么 |
| --- | --- | --- |
| 平台 AI 回答，没有来源 | 找检索词、整理玩法方向；明确标记为平台总结。 | 店铺、营业、价格等关键事实重新查；不能凭摘要完成核验。 |
| AI 回答，带可定位来源 | 复用为研究中间产物，保留平台/模型和底层来源关系。 | 核对引用是否实际支持主张，检查时间和适用条件。 |
| 搜索条目、摘要及 ID/链接 | 做候选召回、去重和相关性排序。 | 对选中的候选读取有权限的详情；无法获取时降低结论强度。 |
| 原文/视频文本与评论 | 提取体验、适用人群、排队/避坑线索。 | 识别广告、重复与时间范围；事实再与官方或地图核验。没有视频文本时不声称看过视频。 |

建议从每主题 10～20 条候选、精选 5～10 条详情起步；需要时逐批扩到 50 或配置上限。这是实验起点，不是已测最优值，也不是承诺各平台都支持这些数量。

只有在底层来源可用、API 权限允许并且预算接受时，才比较“平台总结”“TOP10”“TOP50”和“分批扩展”。记录漏掉的关键事实、来源可定位率、重复率、总耗时和费用。多取 40 条若没有带来信息增益，就不继续付出解析成本。

## 8. 调研过程与限制

- 查询主题：旅行 AI 产品；多 Agent 旅行仓库；小红书官方搜索/授权/社区 MCP；知乎官方搜索；抖音官方搜索；高德；美团；国内模型搜索；供给与天气接口；编排、约束与追踪组件。
- 证据优先顺序：平台官方文档与产品页、项目原仓库。第三方文章只用于发现入口，没有把它们作为关键接口参数的依据。
- 主要修正：知乎已有官方搜索/直答入口；抖音旧关键词管理接口与新视频垂搜不同，矩阵采用当前读到的新接口；不能沿用“这些平台都无官方接口”的泛化判断。
- 访问缺口：知乎与美团部分正文不可提取；火山文档多次超时；Google 旧样例 raw 地址 404。对应能力降低核验等级，不补造细节。
- 没有做：竞品真机试用、业务账号登录、接口资格申请、第三方采集服务购买、社区 MCP 安装、商业成本压测和代码安全审计。
- 本文件保存公开链接及简短研究结论，不复制攻略全文，不包含账号密钥、Cookie 或真实用户旅行数据。

## 9. 下一步验证清单

1. M1 先写离线预算、目的地及证据结构，无账号依赖。
2. M2 用一个国内模型、一个搜索源和高德跑同一小样本，保存脱敏响应和真实失败情况。
3. 按实际账号资格验证知乎/抖音；确认费用和留存权限，更新本矩阵为真实调用等级。
4. 使用同一需求试用竞品，记录人需要补改多少工作，验证项目差异是否成立。
5. 明确平台合作后再决定小红书、美团与票务接入路线，不让未确定的数据源卡住整个项目。
